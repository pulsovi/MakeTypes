# Create soft-fail early-return
**Status:** delivered
**Delivered:** 2026-09-15
**Labels:** `bug` · `docs`

## Summary

Generated proxy `Create` still assumes validation abort via throw. After `errorHelper` stopped throwing systematically, failed structural checks fall through into field / `Object.keys` / constructor work and can raise incidental `TypeError`s (e.g. property access on `undefined`). Behaviour must match [Create soft-fail early-return](../../../docs/adr/0001-create-soft-fail-early-return.md).

## Verification (triage)

> *This was generated by AI during triage.*

**Confirmed.** Emitted `checkRecord` returns a boolean and does not abort; record `Create` ignores that result, then walks fields and `Object.keys(d)`. Soft `errorHelper` only optionally calls `handleProxyError`. `checkRecord` call sites also pass `(field, value, type)` while the helper is defined as `(value, field, type, …)`. No prior rejection in `.out-of-scope/`. No existing early-return-on-failed-check implementation found under emitted `check*` / `Create` continua.

## Acceptance criteria

- [x] On the first failed check in a generated `Create` continuum (`check*` false, or unknown-property), if `shouldThrow` applies then `errorHelper` runs; if it returns, `Create` returns the input value unchanged and runs no further checks in that invocation
- [x] When every check in that `Create` succeeds, `Create` returns `new …Proxy(input)` (record path) as today for the success case
- [x] The same early-exit contract applies to every generated continuum that would otherwise keep doing assumed-valid work after a failed check (record `Create`, root non-record `Create`, collection checks, nested `Create`)
- [x] Nested `Create` soft-fail stops only that nested invocation; the parent continues its remaining checks and may still construct its Proxy
- [x] `Create` honours `shouldThrow` (union / `checkMulti` probes can fail a branch without calling `errorHelper`)
- [x] `checkMulti` arms return a boolean success for the branch (not truthiness of `Create`'s value); record arms use `v instanceof ThatProxy`; primitive arms use the `check*` boolean
- [x] `checkRecord` call argument order matches the helper signature `(value, field, type, shouldThrow?)`
- [x] README no longer claims a Proxy instance is still returned on mismatch when the handler does not throw; it matches the ADR (soft path returns raw input)

## Out of scope

- Re-entering `Create` with an already-built Proxy that then soft-fails (V1)
- Changing `handleProxyError`'s callback shape or making throwing the default again
- New public APIs beyond what the ADR requires for `shouldThrow` / success signalling

## Agent Brief

**Category:** bug
**Summary:** Align generated `Create` with soft `errorHelper` — early-return raw input on first failed check; fix `checkMulti` boolean arms and README

**Current behavior:**
`errorHelper` no longer throws by default. Emitted `check*` helpers return booleans after optionally calling `errorHelper`, but record (and related) `Create` paths ignore those results and continue field walks, unknown-property scans, and Proxy construction. Invalid non-object input can therefore throw incidental `TypeError`s instead of soft-failing. `checkMulti` arms still treat assignment / `Create` return truthiness as branch success. README still says the Proxy is returned on mismatch when no handler throws.

**Desired behavior:**
Per `docs/adr/0001-create-soft-fail-early-return.md`: first failed check → `errorHelper` when `shouldThrow` says so → if that returns, return input unchanged and stop further checks in that `Create`; all checks OK → construct Proxy. Nested soft-fail is local only. `checkMulti` arms return real booleans (`instanceof` for record arms). `shouldThrow` is honoured on `Create`. README matches the ADR. `checkRecord` arguments are in signature order.

**Key interfaces:**
- Generated `Create` — return raw input on soft failure; Proxy instance only on full success; accept / honour `shouldThrow`
- Emitted `checkRecord` / `check*` / `checkMulti` — boolean results must drive early-exit; `checkMulti` callbacks return boolean branch success
- `errorHelper` / `handleProxyError` — remain the only throw opt-in; do not restore systematic throw inside `errorHelper`
- README runtime-error section — align with ADR soft-return semantics
