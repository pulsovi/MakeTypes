# Create soft-fail early-return

Generated proxy `Create` paths must not assume `errorHelper` never-returns. After the first failed check (`check*` false, or unknown-property), call `errorHelper` when appropriate; if that returns, **return the input `d` unchanged** and run no further checks. Only when every check succeeds do we `return new …Proxy(d)`. This applies to every generated continuum that would otherwise keep doing assumed-valid work (record `Create`, root Emitter `Create`, collection checks, nested `Create`). A nested `Create` soft-fail stops only that nested invocation; the parent continues its remaining checks and may still construct its Proxy. `checkMulti` arms must return a **boolean** success for the branch — not the truthiness of `Create`'s value. For record arms, success is `v instanceof ThatProxy` (Proxy only on full success; soft-fail returns raw `d`); primitive arms return the `check*` boolean. Re-entering `Create` with an already-built Proxy that then soft-fails is out of scope for V1. `Create` must honour `shouldThrow` so union probes can fail a branch without calling `errorHelper`. It supersedes the README claim that a Proxy instance is still returned on mismatch when the handler does not throw — the soft path returns the raw input instead.
